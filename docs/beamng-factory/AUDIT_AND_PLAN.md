## 1. Технический аудит возможностей

Проверено по исходникам **BeamNGpy 1.36** (последняя версия на PyPI, скачана и разобрана).
Ниже перечислены только методы, которые реально есть в библиотеке.

### 1.1 Подключение к игре
| Что | Реальный API | Примечание |
|---|---|---|
| Запуск игры и подключение | `BeamNGpy(host, port, home=...)`, `bng.open(launch=True)` | Игра запускается с аргументами `-tcom`, Python общается по TCP (порт 25252) |
| Проверка лицензии tech | `bng.tech_enabled()` | В BeamNG.drive возвращает `False`, часть датчиков недоступна (см. 2) |
| Закрытие | `bng.close()`, `bng.control.quit_beamng()` | |

### 1.2 Сцены и карты
| Что | API |
|---|---|
| Список карт и сценариев | `bng.scenario.get_levels()`, `get_levels_and_scenarios()` |
| Создание сценария | `Scenario(level, name)`, `scenario.add_vehicle(v, pos, rot_quat)`, `scenario.make(bng)` |
| Загрузка / старт / рестарт | `bng.scenario.load()`, `start()`, `restart()`, `stop()` |
| Дорожная сеть карты | `bng.scenario.get_road_network()`, `get_roads()`, `get_road_edges()` |
| Свои дороги и препятствия | `scenario.add_road()`, `add_mesh_road()`, `add_procedural_mesh()` (рампы, блоки), `add_checkpoints()` |
| Телепорт объектов | `bng.scenario.teleport_object()`, `vehicle.teleport()` |

### 1.3 Автомобили
| Что | API |
|---|---|
| Модель, конфигурация, цвет | `Vehicle(vid, model='etk800', part_config=..., color=...)`, `vehicle.set_color()` |
| Доступные машины | `bng.vehicles.get_available()` — список берём **из игры**, а не выдумываем |
| Прямое управление | `vehicle.control(throttle, steering, brake, parkingbrake, clutch, gear)` |
| Скорость мгновенно | `vehicle.set_velocity(speed, dt)` |
| Детали, шины, свет | `set_part_config()`, `deflate_tire()`, `set_lights()`, `set_esc_mode()` |
| Восстановление | `vehicle.recover()` |
| Своя Lua внутри машины | `vehicle.queue_lua_command(...)` |

### 1.4 Встроенный AI водитель
`vehicle.ai.set_mode()` — режимы: `disabled, random, traffic, span, manual, chase, flee, stopping`.

| Действие сценария | Как реализуем |
|---|---|
| «едет по трассе» | `ai.drive_in_lane(True)`, `ai.set_speed(kmh/3.6, 'limit')`, `ai.set_waypoint()` |
| «погоня» | `ai.set_target(id, 'chase')`, `ai.set_aggression()` |
| «убегает» | `ai.set_target(id, 'flee')` |
| точная траектория (столкновение, занос) | `ai.set_script([{x,y,z,t}, ...])` — машина проходит точки в заданное время, это главный инструмент для гарантированных аварий |
| линия с заданной скоростью | `ai.set_line([{pos, speed}, ...])` |
| трафик на фоне | `bng.traffic.spawn(max_amount)`, `traffic.start()`, `traffic.stop()` |

### 1.5 Время, физика, окружение
| Что | API |
|---|---|
| Пауза / шаги физики | `bng.control.pause()`, `resume()`, `step(n)` |
| Детерминизм | `bng.settings.set_deterministic(steps_per_second)` — повторяемость дублей |
| Время суток, погода, гравитация | `bng.env.set_tod()`, `set_weather_preset()`, `set_gravity()` |
| Произвольная Lua в игре | `bng.control.queue_lua_command("...")` — для slow-motion (`simTimeAuthority.set(0.25)`), скрытия интерфейса и т.п. |

### 1.6 Камеры
| Что | API |
|---|---|
| Свободная камера (дрон, кинематограф, статика) | `bng.camera.set_free(pos, direction)` — ставим каждый кадр из Python, получаем любые траектории |
| Камера, привязанная к машине | `bng.camera.set_relative(pos, dir, up)` |
| Штатные режимы игрока | `bng.camera.set_player_mode(vehicle, mode, config)`, `get_player_modes()` (orbit, chase, driver, external…) |

### 1.7 Данные для «режиссёра» (что произошло в дубле)
| Что | API |
|---|---|
| Позиция, скорость, направление | датчик `State` / `vehicle.sensors.poll()` |
| Повреждения | датчик `Damage` (сумма урона) |
| Перегрузки (удар) | датчик `GForces` |
| Электрика (обороты, скорость) | датчик `Electrics` |

Этих данных достаточно, чтобы автоматически решить: «столкновение произошло?», «машина перевернулась?» (вектор `up`), «дубль удался?».

## 2. Ограничения (честно)

1. **BeamNG.drive vs BeamNG.tech.** BeamNGpy работает с обычной BeamNG.drive, но датчик `Camera` с выдачей кадров (shared memory), лидар и аннотации — функции BeamNG.tech (платная/исследовательская лицензия). Поэтому **видео пишем не через API, а захватом экрана** (FFmpeg/OBS). Управление машинами, AI, камерой, погодой, физикой — работает в .drive. На этапе 0 программа сама проверит `tech_enabled()` и что именно доступно в вашей версии игры.
2. **Запись — только на вашем Windows ПК.** Игра и запись физически работают у вас. Я разрабатываю и тестирую логику здесь на «эмуляторе игры» (mock), а финальные проверки с реальной BeamNG делаем вместе на вашем компьютере.
3. **Детерминизм не 100%.** Мягкотельная физика чувствительна к мелочам; авария в каждом дубле немного другая. Поэтому есть автоматическая проверка дубля и пересъёмка.
4. **Slow-motion в реальном времени.** Замедление через `simTimeAuthority` даёт плавную картинку при захвате; дополнительно можно замедлять в монтаже (интерполяция FFmpeg `minterpolate`).
5. **Список машин и карт — из игры.** Названия моделей (`etk800`, `pickup`, `us_semi`, …) и карт (`west_coast_usa`, `italy`, `gridmap_v2`, …) система считывает из вашей установки, включая моды.
6. **Понимание сценария.** Свободный русский текст надёжно разбирается через LLM (Claude API) в строгую JSON-схему. Без интернета/ключа работает упрощённый разборщик по ключевым словам (меньше возможностей, но работает).
7. **Музыка и звуки.** Нужны файлы без авторских претензий. Встроим библиотеку: ваши файлы + генерация звуков/озвучки через ElevenLabs (у вас уже подключён). Звук самой игры тоже пишется.
8. **Версии игры.** Обновления BeamNG иногда ломают совместимость BeamNGpy; фиксируем пару версий «игра ↔ beamngpy» в настройках и проверяем при старте.

### Ключевые решения
- **Сценарий → JSON-схема (pydantic).** Сцена = локация, погода, время, актёры (тип/цвет/роль), действия (`accelerate, follow_road, overtake, chase, flee, crash_into, swerve, jump, rollover, stop, explode-style damage`), длительность, «главный момент».
- **Действие → «манёвр».** Каждое действие — класс-плагин с методами `prepare()`, `run()`, `success_check()`. Новые манёвры добавляются одним файлом (расширяемость).
- **Гарантированная авария.** Планировщик вычисляет точку встречи на реальной дороге, обе машины получают `ai.set_script` с таймингами так, чтобы прийти в точку одновременно; для «теряет управление / переворот» — резкий руль через `vehicle.control`, при необходимости рампа `add_procedural_mesh`.
- **Камеры.** Python-контроллер 30–60 Гц вызывает `camera.set_free()` по траекториям: Follow (сзади со сглаживанием), Front (перед машиной, смотрит назад), Drone (облёт по орбите сверху), Cinematic (статичная точка у места события + плавный поворот), Slow Motion (Cinematic + замедление времени на «главном моменте»), Replay (повтор события: перезапуск того же детерминированного дубля с другой камерой). Режиссёр камеры выбирает тип по действию и времени до события.
- **Запись.** По умолчанию FFmpeg `gdigrab`/`ddagrab` (окно игры) + WASAPI-звук, кодек NVENC/AMF/x264 по наличию. Альтернатива — OBS через obs-websocket v5 (`obsws-python`). Каждый дубль — отдельный файл + JSON событий (время удара, позиции).
- **Автовосстановление.** Watchdog: если игра не отвечает/вылетела — убить процесс, перезапустить, продолжить с той же сцены (состояние производства сохраняется после каждого дубля).
- **Монтаж.** MoviePy 2 для сборки + FFmpeg для тяжёлых операций. Звуки удара ставятся по таймкоду из датчика `Damage`/`GForces`. Для 9:16 — кроп, который следует за проекцией машины на экран.

## 4. Библиотеки

| Назначение | Библиотека |
|---|---|
| Управление игрой | `beamngpy==1.36` (версия фиксируется под вашу игру) |
| GUI | `PySide6` (Qt 6, тёмная тема, встроенный видеоплеер `QMediaPlayer`) |
| Модели данных / схемы | `pydantic` v2 |
| Разбор сценария | `anthropic` (Claude API) + встроенный правиловый парсер |
| Запись | `ffmpeg` (бинарь), опционально `obsws-python` |
| Монтаж | `moviepy` 2.x, `numpy`, `opencv-python` (анализ кадров, кроп) |
| Звук | `pydub`/ffmpeg, ElevenLabs API (SFX/озвучка, опционально) |
| Процессы / окна Windows | `psutil`, `pywin32` (фокус окна игры, его координаты) |
| Логи | `loguru` |
| Сборка в .exe | `PyInstaller` + установщик Inno Setup |
| Тесты | `pytest` + mock-бэкенд BeamNG |

## 6. План реализации (поэтапно)

| Этап | Результат | Где проверяется |
|---|---|---|
| **0. Проверка связи** | Скрипт `doctor`: находит игру, запускает через BeamNGpy, читает список машин/карт, ставит машину, двигает камеру, пишет 10 с видео FFmpeg. Отчёт что доступно в вашей версии | **ваш ПК** (1 запуск) |
| **1. Ядро** | Схема сценария, проект/папки, логи, конфиг, mock-бэкенд, тесты | здесь |
| **2. Режиссёр** | Текст → JSON (Claude + офлайн), каталог синонимов машин/цветов/карт | здесь |
| **3. Игровой контроллер** | Построение сцены, манёвры: езда, обгон, погоня, бегство, столкновение (set_script), занос/переворот, прыжок с рампы; датчики и валидатор | mock здесь, реальная игра у вас |
| **4. Камеры** | 6 типов камер + автоматический выбор ракурсов | у вас |
| **5. Запись** | FFmpeg (и OBS опционально), авто старт/стоп, пересъёмки, watchdog | у вас |
| **6. Монтаж** | Склейка, обрезка пауз, переходы, SFX по ударам, музыка, 16:9 и 9:16 | здесь на тестовых клипах |
| **7. GUI** | Окно BEAMNG YOUTUBE FACTORY со всеми элементами из ТЗ, пауза/стоп/возобновление | здесь (скриншоты) + у вас |
| **8. Упаковка** | `.exe` + установщик для Windows 11, инструкция | у вас |

Каждый этап — отдельный коммит в ветку `claude/beamng-youtube-factory-mvshnw`, рабочий и проверенный.
